企业知识库智能客服系统 基于 LangChain4j 的 RAG 问答

2026.02 - 至今

把企业内部散落的 PDF / Word / TXT / Markdown 变成能对话、会溯源、答不上来会转人工的客服知识库。不做套壳，重点解决 RAG 落地的三个真问题：文档怎么切才不丢语义、检索不准时怎么不胡说、大模型调用太贵怎么办。

Spring Boot Java 17 LangChain4j Chroma 火山引擎方舟 Apache Tika SSE / WebSocket JWT
  • 文档治理：Tika 统一解析多格式；DocumentSplitters.recursive(500, 50) 递归切片，500 字保语义段落完整、50 字重叠保住跨段指代；同名文档按 metadata 先删旧向量再入库，知识库不越滚越脏。
  • 检索兜底防胡说：寒暄词表短路 → 指代消解改写独立问题 → Chroma Top3 且相似度 ≥ 0.3 才放行 → Prompt 明确「仅依据片段回答」。检索没命中就走兜底话术，绝不硬答。
  • 三级缓存降本：改写 30min / 检索 1h / 答案 1h，按各层时效性分别设 TTL。高频重复问题直接命中答案缓存，省掉 embedding + 检索 + 生成整条链路。
  • 流式与可靠推送：SSE 逐字推送把首字延迟从数秒降到几百毫秒；人工回复走 WebSocket，直推失败重试 3 次后落 Redis 补偿队列，客户端重连补发。
  • 工单闭环：状态机「待处理 → 处理中 → 已完成」，认领时校验状态防两个客服抢同一单；JWT + 拦截器统一鉴权，验证码失败次数计数防爆破。

巷往生活服务平台 本地生活 O2O 高并发后端

2025.09 - 2026.02

覆盖商户浏览、探店笔记、优惠券秒杀等核心模块。重点不在业务堆量，而在把高并发场景下的经典难题做对：热点数据怎么扛、库存怎么不超卖、订单怎么不重复、锁怎么不失效。

Spring Boot 3 Java 21 MyBatis-Plus Redis RabbitMQ Redisson Lua MySQL
  • 缓存三防：Cache Aside 为主干，空值缓存防穿透、逻辑过期 + 互斥锁重建防击穿、TTL 抖动 + 预热防雪崩，三种失效场景分别下药。
  • 秒杀防超卖与一人一单：Lua 脚本把「一人一单校验 + 库存扣减 + 用户记录」压成单次原子操作，在 Redis 层挡掉绝大部分无效流量；成功后投递 RabbitMQ 异步削峰落库，DB 侧以 stock > 0 条件更新 + 应用层防重查询兜底。
  • 分布式锁演进：自研 SETNX 锁 → 发现「误删他人锁」与「业务超时锁提前释放」两个坑 → 演进至 Redisson 可重入锁 + 看门狗续期，完整呈现选型思考过程。
  • 深分页优化：用 Explain 定位到瓶颈不是扫行数而是回表次数，建立联合覆盖索引 + 游标分页（lastId）把 O(n) 降到 O(log n)。
